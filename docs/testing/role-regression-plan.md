# 五类角色业务回归计划

执行日期：2026-10-03。基线：`eb5cd5e246bdc8a2854fc834df05fc8440494e37`。本轮只执行回归和登记问题，不修复产品逻辑。

## 环境与方法

- 使用本机 Docker 开发环境：前端 3010、API 8010、Casdoor 8000，三个业务/公共数据库及 MinIO、Redis。
- 真实登录五类账号，通过 HTTP 检查状态推进、写入读回、跨角色交接及越权拒绝；浏览器验证角色入口、页面加载和典型操作。HTTP 200 不能单独证明业务成功。
- 新数据统一以前缀 `REG-20261003-` 区分，案件/检查/考核/系统分别使用独立后缀。只操作本轮测试数据，不修改既有种子、五类账号权限和其他项目资源。
- 凭据仅从被 Git 忽略的 `.local/dev-accounts.json` 读取，不进入报告。详细本地证据保存在 `.local/regression/`，可复跑脚本和脱敏摘要进入项目文档。
- 发现失败先核查输入契约、真实响应、读回及服务日志，合并相同根因。合法前置失败后的下游登记 BLOCKED；不能通过改库跳状态制造通过结果。

## 角色与主流程

| 角色 | 业务范围 | 必测交接及边界 |
|---|---|---|
| 系统管理员 | 字典、角色、菜单、组织人员、流程/任务模板；公共身份和文件 | 创建修改读回、重复值、受保护配置、非管理员拒绝 |
| 总部业务 | 案件处理、外聘协作、费用/结案；检查全链；考核方案及复核 | 向业务部门/律师/分支分派，收回材料，复核与结果 |
| 分支机构 | 自有线索与协查、检查资料/确认/整改、考核填报举证 | 只见本机构范围；提交后总部读回；拒绝管理功能 |
| 业务部门 | 线索上报、上报记录、协查任务 | 总部接收、任务反馈；拒绝检查考核和系统管理 |
| 外聘律师 | 委托案件、任务、资料/进展反馈 | 已分派可见可办理，未分派拒绝，拒绝内部管理 |

## 业务分组

1. 案件：线索 → 转案/立案 → 成员/任务 → 卷宗/附件 → 财务/外聘 → 结案/归档；门户和查询统计。
2. 检查：计划 → 审批/启动 → 资料 → 底稿/发现 → 确认/申诉 → 报告 → 整改/关闭。
3. 考核：指标规则 → 方案周期 → 发布下发 → 分支填报举证 → 总部退回/复核 → 结果申诉/归档。
4. 公共：五角色登录和边界、统一字典多端读回、组织权限及系统模板维护。
5. 浏览器：五角色入口、主要菜单页面、典型表单保存和错误反馈，与 API 结果交叉验证。

## 结果与登记标准

- PASS：检查点预期满足且有真实响应或页面证据。
- FAIL：合法操作可复现失败或越权、错误数据/状态、页面契约不一致。
- BLOCKED：依赖的前置失败或当前环境未配置外部服务，后续不能独立完成。
- NOT RUN：本轮未执行，不能计为通过。
- P1：主业务流程不能完成或权限/数据隔离失效；P2：局部功能错误、校验或管理维护失败；P3：非阻塞显示及提示问题。

“完整业务回归”按现有业务主链与角色责任执行，不等同于所有字段组合、性能/压力、安全渗透或真实外部 OA/EKP/AI 联调。报告必须列明受阻及未覆盖范围。
