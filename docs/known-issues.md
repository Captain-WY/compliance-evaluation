# 已知问题与后续范围

本页汇总合并后项目的已知限制。合并基本测试、五角色业务回归和导航验收的执行范围不同，后续发现的缺陷不因较早的基本测试通过而关闭。

## 2026-10-03 五角色业务回归

该轮完成真实API、浏览器和重启读回，发现18项确认缺陷，另登记2项能力缺口和1项业务规则待确认；当时未修复产品。当前状态统一查总表，不在本页重复维护。

详见 [任务简报](testing/role-regression-report.md) 和 [问题台账](testing/role-regression-issues.md)。以下合并验收数据为历史记录，不覆盖本轮缺陷结论。

## 原系统基线

- M0 中原案件前端构建通过，但曾有 114 条 TypeScript 诊断；合并后的实际检查结果以基本回归报告为准。
- 原后端完整测试存在历史失败：合规侧 433 通过、10 失败、3 错误；案件侧 23 通过、5 失败，另有 25 项受外部服务阻塞。这些是历史基线，不能当作合并后测试结果。
- 深层审批流、所有角色页面、报表、搜索与外部智能服务不在本次简单回归范围。

## 当前合并版本

- 前端 `npm run build` 通过；`npm run typecheck` 剩余 32 条诊断（案件业务 28 条、合规考核工作台 4 条），未跳过类型检查。完整输出保存在本机 `.local/frontend-typecheck-final.log`。
- 旧演示页面仍可能存在静态数据；前端显示开发阶段提示，对尚未接入的保存动作明确返回错误。检查详情中的 EKP 联控展示仍有历史占位字段，不能作为外部流程已执行的证据。未接入的 AI 会话/聊天及 EKP 提醒明确返回不可用。
- 检查计划保留内存工作集并持久化完整状态，目前以单 API worker 运行，多实例并发一致性未验收。
- 锁文件安装审计报告 23 项依赖问题（5 low、5 moderate、12 high、1 critical）；本次未执行可能破坏兼容性的批量升级，后续部署到生产前需复核并升级相关依赖。
- 前端主 bundle 较大，存在构建体积提示；拆包优化留待后续。

## 后续建议

按已确认的[轻量迭代方法](development/iteration.md)，分别推进案件管理、合规检查和系统管理。优先复核公共写入事务、检查附件权限及案件/检查主链阻塞；合规考核（含周期与履职台账）专项修复暂缓，保留原严重性。暂缓不表示相关风险已经解决。历史类型诊断和未接入页面按批次实际影响安排，不作为所有任务的统一前置条件。

请勿将页面上的历史演示数据或未实现动作当作已持久化业务能力。合并阶段记录见[基本回归](testing/smoke-report.md)，业务结论见[五角色报告](testing/role-regression-report.md)，左侧导航及页面容器的检查见[导航验收](testing/navigation-regression.md)。
